# Схема обмена данными с внешними системами (Этап 5)

## Цепочка

```
SQLite edu.db
   |  queries.py (параметризованные SQL-запросы)
   v
Внутренняя структура (списки словарей Python)
   |                         |
   v                         v
report.json              report.xml
   |                         |
   v                         v
Внешняя система 1        Внешняя система 2
(принимает JSON)         (принимает XML)
```

Одна и та же внутренняя структура экспортируется в оба формата, после чего
оба файла читаются обратно и сверяются (`export_data.py` печатает
«структуры совпадают: True»). На первой и последней стадии цепочки работает
безопасный разбор внешних ответов.

## Безопасный разбор внешнего ответа

Проверки идут ДО `json.loads`, в порядке дешевизны:

1. пустой ответ -> `{"error": "empty_response"}`;
2. ответ не начинается с `{` или `[` -> `{"error": "not_json", "preview": ...}`
   (реальный случай из data/final/api_response_error.html: пришла HTML-страница
   502 Bad Gateway - она ловится именно здесь);
3. JSON битый -> `{"error": "invalid_json", "detail": ...}`;
4. JSON валидный, но без обязательных полей -> `{"error": "missing_fields", "detail": ...}`.

Ошибка возвращается как данные (словарь с ключом error), а не как исключение -
вызывающий код не падает и может решить, что делать с отказом.

## Когда JSON практичнее, а когда XML

**JSON практичнее**, когда обе стороны - программы: он компактнее, разбирается
одной строкой (`json.load`), совпадает со словарями Python, легко читается
человеком, и почти все современные веб-сервисы принимают именно его. Минус -
строгий синтаксис (запятые, кавычки) и отсутствие схемы в самом документе:
поля договорились проверять вручную.

**XML практичнее**, когда данные идут во «взрослые» корпоративные системы:
строгая схема (XSD) проверяет документ автоматически, есть namespaces и
атрибуты, документы можно комментировать прямо внутри, и часть старых
государственных/банковских обменов требует именно XML. Минус - многословие:
на те же данные уходит заметно больше байт, и разбор тяжелее.

В нашем случае: отчёт отдаётся одинаковым содержимым в обоих форматах, чтобы
принимала любая из двух систем; выбор формата - за принимающей стороной.
