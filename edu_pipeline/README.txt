================================================================
 ПРОЕКТ edu_pipeline - обработка заявок онлайн-платформы «НОРД-Класс»
 Инструкция запуска простым языком
================================================================

О ЧЁМ ЭТОТ ПРОЕКТ

Платформа принимает заявки студентов на курсы. Внешний оператор каждый день
присылает «сырой» файл с заявками: в нём есть и правильные строки, и
ошибочные. Этот проект принимает файл, проверяет каждую строку и объясняет
каждый отказ, загружает хорошие заявки в базу данных, строит аналитический
отчёт, выгружает итоги двум внешним системам (одна понимает JSON, другая -
XML) и сопровождается автоматическими тестами.

Проект разбит на 7 этапов, как в задании: ноутбука с показателями, очередь
проверки, валидаторы, база данных с транзакциями, ETL и обмен, класс заявки
с историей, тесты с разбором чужих ошибок и диагностикой кодировок.

ЧТО НУЖНО ДЛЯ ЗАПУСКА

1. Python 3.10 или новее (бесплатно ставится с python.org; при установке
   в Windows отметьте галочку "Add Python to PATH").
2. Дополнительных библиотек НЕ нужно - всё на стандартном наборе Python.
   Единственное исключение - аналитический ноутбук (шаг 11): если пакет
   Jupyter/nbconvert не установлен, run_all.py сам предложит поставить его
   во время прогона - достаточно согласиться (нужен интернет). Вручную это
   одна команда: python -m pip install notebook nbconvert. Даже совсем без
   этого пакета прогон пройдёт: ноутбук уже выполнен и лежит в проекте.

ВАЖНО ПРО ИСХОДНЫЕ ДАННЫЕ

Файлы в папке data/final/ - исходники. Проект их НИКОГДА не меняет.
Все результаты работы появляются в папке results/. Если папку results/
удалить - при следующем запуске всё пересоздастся само.

КАК ЗАПУСТИТЬ С ЧИСТОГО СОСТОЯНИЯ

Самый простой способ - ОДНА команда. Откройте командную строку в папке
проекта (edu_pipeline) и выполните:

      python run_all.py

Он сам удалит results/, выполнит шаги 1-11 по порядку, напечатает ход
работы, в конце покажет чек-лист файлов в results/ и подскажет, если
Jupyter для ноутбука не установлен. Больше ничего запускать не нужно.

Как открыть командную строку прямо в папке проекта: откройте edu_pipeline
в Проводнике, щёлкните левой кнопкой по пустому месту адресной строки
вверху окна, сотрите там всё, напечатайте cmd и нажмите Enter - откроется
чёрное окно, которое уже «внутри» папки. В PyCharm ещё проще: откройте
проект и перейдите на вкладку Terminal внизу окна.

Если хотите проходить этапы по отдельности (например, чтобы посмотреть
каждый шаг), те же шаги руками:

  1)  python create_db.py
      (создаст results/edu.db - базу с справочником студентов и курсов)

  2)  python batch_load.py
      (докажет транзакции: results/transaction_protocol.txt - валидный пакет
       записывается, ошибочный откатывается целиком, частичных изменений нет)

  3)  python etl_import.py
      (проверит заявки и загрузит хорошие в базу: results/edu.db;
       results/rejected_enrollments.csv - отклонённые с причинами;
       results/etl_report.txt - сводка. Запускать можно много раз:
       дублей не будет)

  4)  python export_data.py
      (results/report.json и results/report.xml - выгрузки для внешних
       систем; программа сверит их между собой и покажет, как разбирается
       «неправильный» внешний ответ вроде HTML-страницы с ошибкой)

  5)  python review_queue.py
      (покажет очередь заявок, ждущих проверки оператора, двумя разными
       способами и докажет, что результаты совпадают;
       results/pipeline_comparison.md - таблица сравнения)

  6)  python normalize_audit.py
      (приведёт «грязный» журнал операторов к единому виду:
       results/before_after.csv - было/стало;
       results/expected_actual.csv - сверка с эталоном)

  7)  python demo.py
      (демонстрация класса заявки: смена статусов, запрет запрещённых
       переходов, защита журнала истории)

  8)  python unicode_diagnostics.py
      (разберётся с кодировками двух файлов имён:
       results/diagnostic_table.csv - таблица попыток и выводов)

  9)  python measure_performance.py
      (results/performance.txt - замеры скорости timeit)

  10) python -m unittest discover -v > results/tests_green_log.txt
      (34 автоматических теста; в конце должно быть напечатано OK.
       Лог сохранится в results/tests_green_log.txt)

  11) Ноутбук (аналитический отчёт):
      jupyter nbconvert --to notebook --execute report_enrollments.ipynb --inplace
      Либо откройте report_enrollments.ipynb в Jupyter и нажмите Run All.
      В ноутбуке - 7 показателей и выводы для руководителя с цифрами.

- Ноутбук: 332 000 ₽ потенциальной выручки по активным заявкам.

ЧТО РЕАЛИЗОВАНО (по этапам)

Этап 1. Аналитический ноутбук (report_enrollments.ipynb)
  Считает 7 показателей: объём сырых данных, качество строк (валидность
  по полям), заявки по статусам, заявки по курсам, средняя длительность
  по курсам, потенциальная выручка по активным заявкам (цена курса ×
  число заявок), распределение по форматам обучения. У каждого
  показателя - интерпретация с цифрами и выводы для руководителя.
  Считается на чистом Python прямо из CSV-файлов, воспроизводится
  кнопкой Run All (или шагом 11 run_all.py).

Этап 2. Очередь проверки заявок (review_queue.py)
  Собирает очередь заявок, ждущих проверки оператора, ДВУМЯ разными
  способами: pipeline_deque (списковая сборка + deque - честная очередь
  FIFO) и pipeline_filter_map (filter + map + sorted). Программа
  доказывает, что результаты совпадают (списки ID заявок равны), а
  исходные строки файла при этом не изменяются ни в одном варианте.

Этап 3. Валидация и нормализация (validators.py, normalize_audit.py)
  Все правила проверки полей заявки собраны в одном модуле: номер
  заявки, почта, курс, статус, дата, длительность, формат строки.
  Правила построены на re.fullmatch с именованными группами и обратной
  ссылкой, поэтому причина отказа читается по имени правила. Нормализация
  журнала операторов приводит «грязные» строки к единому виду и
  сверяется с эталоном: было/стало - в before_after.csv,
  сверка - в expected_actual.csv.

Этап 4. База данных и транзакции (create_db.py, queries.py, batch_load.py)
  SQLite: три таблицы (студенты, курсы, заявки) с первичными и внешними
  ключами и уникальным номером заявки; foreign keys включены явно. Все
  запросы параметризованы (знаки ?) - конкатенации значений нет. Пакетная
  загрузка доказывает транзакции: валидный пакет записывается целиком,
  пакет с ошибкой откатывается целиком - частичных изменений нет.
  Дополнительно есть :memory:-версия базы для тестов.

Этап 5. ETL и обмен данными (etl_import.py, export_data.py)
  Конвейер разделён на приём / проверку / загрузку. Каждая строка сырья
  проверяется правилами этапа 3; у отклонённых строк собираются ВСЕ
  причины через точку с запятой, они попадают в rejected_enrollments.csv.
  Повторный запуск не создаёт дублей (уникальный индекс + INSERT OR
  IGNORE). Выгрузки для внешних систем строятся в JSON и XML с одинаковым
  содержимым (программа сверяет структуры), а «неправильный» внешний
  ответ (пустой, HTML-страница, битый JSON, ответ без нужного поля)
  разбирается без падения программы - проверка выполняется ДО json.loads.

Этап 6. Класс заявки (enrollment.py, demo.py)
  Заявка - объект с закрытым полем статуса: присваивание идёт через
  property, которое разрешает только допустимые переходы
  (new -> on_review -> enrolled -> completed) и запрещает остальные
  с понятной ошибкой. Журнал истории изменений выдаётся копией - снаружи
  его нельзя подменить. У класса есть type hints и docstring.

Этап 7. Тесты, отладка и кодировки
  34 автоматических теста (unittest): валидаторы, класс заявки,
  транзакции на :memory:-базе и регрессионные тесты исправленных чужих
  дефектов. Чужой дефектный модуль buggy_report.py разобран по циклу
  «симптом -> воспроизведение -> причина -> исправление -> тест»,
  исправление живёт отдельно в fixed_report.py (исходник не тронут).
  Замеры timeit: два pipeline сопоставимы по скорости, а deque.popleft
  на 10 000 элементов в разы быстрее list.pop(0). Кодировки: таблица
  попыток чтения двух файлов имён в разных кодировках и вывод, какой
  файл в какой кодировке и почему.

БИБЛИОТЕКИ (что именно используется)

Сторонних пакетов НЕТ - весь код на стандартной библиотеке Python.
Из внешних только Jupyter/nbconvert для шага 11 (ноутбук), и то
необязательно: run_all.py предложит установить его сам.

Стандартная библиотека, по модулям:

- sqlite3   - база данных: схема с ключами, включение foreign keys,
              параметризованные запросы (?), транзакции commit/rollback,
              :memory:-база для тестов. Используют create_db.py,
              queries.py, batch_load.py, etl_import.py и тесты.
- re        - проверка полей и нормализация журнала: fullmatch,
              именованные группы, обратные ссылки (validators.py,
              normalize_audit.py, enrollment.py).
- collections - очередь deque (FIFO за константное время; сравнение с
              list.pop(0) есть в замерах), defaultdict (группировка
              заявок по курсам и статусам), Counter (частоты).
- csv       - чтение и запись CSV (DictReader/DictWriter); везде явная
              кодировка (utf-8 или utf-8-sig, чтобы файлы корректно
              открывались в Excel) и newline="".
- json и xml.etree.ElementTree - две выгрузки отчёта и разбор внешних
              ответов (export_data.py).
- unittest  - 34 теста проекта, запуск через discover (шаг 10).
- timeit    - замеры производительности (measure_performance.py).
- datetime  - метки времени в журнале класса заявки и в очереди.
- pathlib   - пути к файлам без разделителей конкретной ОС, поэтому
              проект одинаково работает в Windows и Linux.
- subprocess, shutil, sys, importlib.util - только run_all.py: запуск
              шагов, очистка results/, проверка наличия nbconvert и его
              установка, если пользователь согласится.

ЧАСТЫЕ ВОПРОСЫ

- «Можно ли запустить всё заново?» Да: просто выполните python run_all.py -
  он сам удалит results/ и пересоздаст всё. Исходники не трогаются.
- «Что именно запускать?» Только run_all.py одной командой. Отдельные файлы
  нужны лишь для пошаговой демонстрации этапов (см. список выше).
- «Нужно ли что-то править руками?» Нет. Если какая-то команда сообщила об
  ошибке - проверьте, что вы в папке edu_pipeline и Python установлен.
- «Пишет "python не является внутренней или внешней командой"?» Python не
  установлен или не попал в PATH: поставьте его с python.org, отметив
  галочку "Add Python to PATH", и откройте командную строку заново.
- «Шаг 11 пишет "Jupyter command jupyter-nbconvert not found"?» Так бывает
  на Windows: pip кладёт команды в папку Scripts, которой нет в PATH.
  run_all.py это обходит - он запускает python -m nbconvert. Вручную
  выполняйте так же: python -m nbconvert --to notebook --execute
  report_enrollments.ipynb --inplace
- «Нет Jupyter вообще?» run_all.py на шаге 11 сам предложит установить
  пакет (ответьте Y и дождитесь конца установки - нужен интернет).
  Отказ или отсутствие интернета не валит прогон: ноутбук уже выполнен,
  шаг можно сделать позже командами из подсказки на экране.
- «Почему и JSON, и XML?» Две внешние системы принимают разные форматы;
  содержимое у них одинаковое, проект это сверяет сам.
- «Что с ошибками в данных?» Ни одна строка не выбрасывается молча: у каждой
  отклонённой строки есть причина в rejected_enrollments.csv.
